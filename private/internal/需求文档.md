## 一、产品定位

**一句话：** 面向小微货代从业者的 AI 信息助手，接入 Marvis 桌面端，按需查询运价、追踪船舶、换算汇率、查术语百科。

**目标用户画像：**
- 小微货代公司（员工 < 50 人，占行业 90%）
- 无专职 IT / 数据团队
- 日常高频查询：运价对比、船期确认、汇率换算
- 核心痛点：信息分散在多个网站，切换效率低

**核心差异化：**
- 零部署：Marvis 内即开即用，无需搭建服务器
- 零学习成本：自然语言输入，表格结构化输出
- 公开数据优先：用 web_search 链公开平台，0 成本起步

## 四、技术架构需求

### 4.1 当前架构（v1.0）

```
用户输入 → Marvis Skill 触发 → web_search/web_fetch → 结构化表格输出
```

- 全部在 Marvis 桌面端内闭环，无需外部服务
- 依赖：Marvis 框架（web_search/web_fetch 工具）、公开网页可访问

### 4.2 二期监控架构

```
定时任务 (create_scheduled_task) → Shell/python 脚本
  → web_search / API 查询
  → 对比缓存（上次状态）
  → 状态变更 → notify.py → 四通道推送
```

**定时任务方案：**
- 方案 A：Marvis 内置 create_scheduled_task（主选）
- 方案 B：GitHub Actions（备选，已有模板 monitor.yml）

**推送通道（notify.py）：**

| 通道 | 配置项 | 适用场景 |
|------|--------|----------|
| 企业微信机器人 | Webhook URL | 团队协作 |
| 钉钉机器人 | Webhook URL | 团队协作 |
| QQ邮箱 SMTP | 授权码 + 收发地址 | 个人用户 |
| Bark (iOS) | Bark Key | iOS 轻量推送 |

环境变量 `NOTIFY_CHANNEL` 切换通道，用户通过对话修改。

### 4.3 三期会员 API 架构

```
会员配置 → API Keys 存储（本地加密）
  → 51Tracking / VesselFinder / 船公司 API
  → 数据聚合 → 结构化输出
```

**会员激活方式：**
- Skill 偏好文件存储 API Key
- 首次使用 F3.1-F3.4 时引导配置
- API 用量计数器（防止超额）
