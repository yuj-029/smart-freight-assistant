| 测试维度 | 结果 | 说明 |

| 触发计算 | ⚠️ 有缺口 | 需要用户提供「集装箱到港日期」才能倒推预警时刻；系统无法自动获知具体柜子的到港日 |

- **核心阻塞**：系统缺少「集装箱到港日」数据源。船期追踪能拿到船舶 ETA，但特定提单号/柜号是否在该船上、何时卸船、何时可提，目前公开渠道无法自动获取。

1. **一期可行方案**：让用户手动输入到港日 + 提单号，系统计算预警时间并设置提醒
2. **二期升级方案**：接入 51Tracking/Ship24 免费 API，自动获取柜号状态（已卸船 = 免堆期起算日）
3. 免堆期策略按港口预置为知识库，支持不同船公司差异化策略（如马士基额外 15 天）

### 场景
关注 **上海港 → 汉堡港 40HQ** 运价，波动超过 ±10% 时推送提醒。

| 10% 波动阈值 | ±$329（基于 $3,292 基线） |
| 触发上限 | $3,621+ |
| 触发下限 | $2,963- |
| 数据来源 | shippingeuro.com、Flexport、BRF Logistics |

### 多维度测试结论

| 测试维度 | 结果 | 说明 |
|----------|------|------|
| 基线数据获取 | ✅ 通过 | 公开航运平台可获取即期运价，多家船公司报价可交叉验证 |
| 波动监测 | ❌ 不可行（当前） | **运价非标准化公开 API**，各平台格式不一、更新频率不固定、数据来源混杂（船公司官网/货代报价/平台聚合），无法稳定轮询比对 |
| 触发逻辑 | ✅ 可行 | 一旦有稳定数据源，±10% 阈值计算简单明确 |
| 实用价值 | ✅ 通过 | 运价波动是货代利润核心变量，10% 波动对整柜影响 $300+，预警价值极高 |

### 阻塞点（高风险）
- **致命阻塞**：**无可靠的运价公开 API**。当前运价数据均来自网页抓取，各平台 HTML 结构不统一、更新频率不确定（有的每天、有的每周）、报价口径不一致（有的含 BAF、有的不含）。用 web scraping 做运价监控极不稳定。
- 船公司官方运价多为登录后查询，不对外开放 API。
- 第三方运价指数（如 SCFI、WCI）发布频率为周度，时效性不足以支撑实时波动提醒。

### 建议
1. **降级方案**：以 SCFI 上海出口集装箱运价指数（每周五发布）为跟踪标的，周频检查欧洲航线分指数波动，虽精度低于航线级即期价，但数据源权威稳定
2. **增强方案**：以 shippingeuro.com 或类似聚合平台为单一数据源（固定 URL + 固定 HTML 结构），配合 GitHub Actions 每日抓取比对，代价是数据源变更时需人工维护 CSS 选择器
3. **二期暂缓**：考虑到数据源稳定性风险，建议二期优先完成定时盯箱（有 51Tracking 免费 API），运价波动提醒推迟至三期或找到稳定数据源后再上线
