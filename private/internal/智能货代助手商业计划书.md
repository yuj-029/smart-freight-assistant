# 第 1 章 执行摘要

## 项目愿景

智能货代助手是中国 6 万+ 小微货代企业操作员的 AI 副驾驶——一个零部署、零费用的桌面端自然语言助手，让每个货代操作员都能以对话方式完成运价查询、船期追踪、定时盯箱、文档处理等日常操作，将日均切换 6-8 个系统的碎片化工作流整合为统一的自然语言界面。

## 产品概述

基于 Marvis 桌面端 Agent 框架开发的智能货代助手 Skill，以"外挂增强层"的轻量化定位切入市场，不替代用户现有的 TMS/ERP 系统，而是在其之上增加一层 AI 能力层。一期已实现智能查询五大功能；二期主动监控方案已验证（双通道架构 + GitHub Actions 盯箱模板）；三期文档处理功能开发中。

## 目标市场

中国国际货代行业市场规模约 2.8 万亿元（2025 年），行业高度分散，前 100 家企业市场份额不足 20%。全国注册货代企业约 6.8 万家，其中 90% 以上为员工少于 50 人的小微企业。目标用户为这些企业中的货代操作员（约 200 万从业人员），他们日常工作高度依赖手动操作和碎片化信息检索，存在明确的 AI 提效刚需。

## 核心优势

- **零部署零费用**：内置于 Marvis 桌面端，用户无需任何安装或配置，与竞品年费数万至数十万的 SaaS 形成代际差
- **云+端混合架构**：纯提醒类走云端定时（零边际成本），轮询监控类走 GitHub Actions（免费），实现零基础设施开支的全天候监控
- **技术已验证**：一期智能查询已可用，二期主动监控架构设计完成、GitHub Actions 盯箱模板已就绪，待上线部署

## 商业模式概要

三阶段演进路径：免费期（种子用户积累 + PMF 验证）→ 增值期（个人订阅 9.9-29.9 元/月 + 功能分层）→ B 端期（团队版 99-299 元/月 + 企业定制）。3 年内目标：10 万注册用户，5% 付费转化率，年收入 1,440 万元（基准档预测）。

## 融资需求

本轮为种子轮，计划融资 300 万元人民币，出让 10% 股权，投后估值 3,000 万元。资金主要用于三期文档智能化功能研发（60%）、用户增长与社区运营（25%）、服务器与基础设施（15%）。预计 12 个月内达成 10 万注册用户和 PMF 验证，为天使轮融资铺垫。

# 第 2 章 市场分析

## 2.1 货代行业规模与结构

中国是全球最大的货物贸易国，2025 年进出口总额约 43.8 万亿元（海关总署数据，引用时点值，可能有调整）。国际货运代理作为贸易链条中的关键服务环节，市场规模约 2.8 万亿元（中国国际货运代理协会，2025 年估算）。

行业呈现典型的"金字塔"结构：

| 层级 | 企业数量 | 市场份额 | 典型特征 |
|------|---------|---------|----------|
| 头部（中国外运、中远海运物流等） | 约 100 家 | 约 20% | 自建 TMS，年 IT 投入千万级 |
| 腰部（区域型货代） | 约 5,000 家 | 约 35% | 可能使用 SaaS 类工具，有一定数字化基础 |
| 长尾（小微货代） | 约 6 万家 | 约 45% | 无专职 IT，操作靠微信群+Excel+电话 |

全国注册国际货代企业约 6.8 万家，从业人员约 200 万人。其中 90% 以上企业员工不足 50 人，单人年处理提单量 300-500 票（行业估算）。

## 2.2 数字化趋势与痛点

国际物流数字化正经历三个趋势：

- **运价透明化**：船公司公开运价逐步增多，但分散在数十个网站，操作员手动比价耗时 30-60 分钟/次
- **实时追踪需求**：货主对货物可视化的要求从"到港通知"升级为"全程可见"，操作员需手动登录船公司官网逐个查询
- **AI 辅助办公普及**：2025 年 ChatGPT/豆包等工具已渗透办公场景，但货代行业缺乏垂直领域的 AI 工具

小微货代操作员的典型痛点：

- **日均切换 6-8 个系统（行业估算）**：船公司官网、汇率网站、海关公告、微信客户群、Excel 台账、邮件客户端
- **超过 40% 时间用于信息检索**而非高价值的客户沟通和异常处理（行业估算）
- **旺季差错率显著上升（行业估算）**：旺季订单量翻倍时，人工操作差错率上升 2-3 倍
- **培训周期长**：新人上手需 3-6 个月，期间老员工带教占用大量时间

## 2.3 目标用户画像

| 画像维度 | 特征 |
|----------|------|
| 职位 | 货代操作员 / 单证员 / 客服 / 销售支持 |
| 年龄 | 25-40 岁，日常使用电脑办公 |
| 日均处理量 | 10-30 票货物，涉及 3-5 家船公司 |
| 核心痛点 | 运价比价耗时、船期追踪碎片化、旺季忙中出错 |
| 技术习惯 | 微信重度依赖，对 SaaS 有认知但不愿付费（年费太高） |
| 付费意愿 | 个人愿意为"真正省时间"的工具支付 10-30 元/月 |
| 决策链 | 个人即可决定使用（无需企业审批），口碑推荐为主要传播方式 |

## 2.4 市场时机

三个关键信号表明现在是进入该市场的合适时机：

1. **Marvis 桌面端用户基数**：作为个人桌面助手，Marvis 在货代等专业人群中的渗透为 Skill 类应用提供了零获客成本的直达通道
2. **AI 工具认知普及**：2025-2026 年，中国桌面端 AI 助手日活用户快速增长，用户已习惯"对话即服务"的交互范式
3. **竞品留白**：头部竞品（运小沓、5U AI）聚焦中大型企业和交易闭环，长尾 6 万+ 小微货代市场的个人操作员需求几乎空白

> 市场数据来源：中国国际货运代理协会（CIFA）行业报告、海关总署统计数据、Marvis 内部用户调研。标注"估算"的数据基于行业访谈和合理推断。涉及"日均切换系统数""信息检索时间占比""差错率"等操作层面数据均为行业估算，非精确统计结果。

# 第 3 章 产品与服务

智能货代助手以"AI 副驾驶"为产品定位——不做 TMS/ERP 的替代者，而是作为现有工具链之上的智能外挂层，用自然语言交互统一碎片化的信息获取和任务管理。

## 3.1 模块 A：智能查询

覆盖货代操作员最高频的五大信息检索场景，全部通过自然语言对话完成，无需登录任何网页：

| 功能 | 场景 | 价值 |
|------|------|------|
| 运价查询 | "上海到洛杉矶 40HQ 下周海运费多少" | 聚合马士基/MSC/达飞等主流船公司公开运价，30 秒内出表 |
| 船期追踪 | "查提单 COSU12345678 到哪了" | 直连船公司公开查询页面，秒级返回货物状态 |
| 汇率查询 | "今天美元汇率，折成人民币" | 实时汇率 + 运价自动换算本币 |
| 目的港政策 | "最近出口印尼有什么新规" | 目的国海关政策/特殊要求/禁运品清单检索 |
| 术语百科 | "DDP 和 DAP 区别" | 货代行业术语即时解释 + 实操案例 |

## 3.2 模块 B：主动监控

区别于竞品的被动查询，智能货代助手支持设置自动监控规则，有变化时主动推送，按实现方式分为双通道：

**纯提醒类**（到港提醒、免费期预警）：create_scheduled_task 云端定时调度，到期时 Marvis 双端（PC+手机）推送，零外部依赖。

**轮询监控类**（定时盯箱、运价波动提醒）：GitHub Actions cron 定时脚本 + 用户所选推送通道推送，完全脱离 PC 运行，免费额度远超日常需求（GitHub Actions 2,000 分钟/月，各推送通道均有充足免费额度）。

| 功能 | 模式 | 实现方案 |
|------|------|----------|
| 到港提醒 | 纯提醒类 | 云端定时 → Marvis 双端推送 |
| 免费期预警 | 纯提醒类 | 云端定时 → Marvis 双端推送 |
| 定时盯箱 | 轮询监控类 | GitHub Actions + curl + 用户所选推送通道 → 微信 |
| 运价波动提醒 | 轮询监控类 | GitHub Actions + curl + 用户所选推送通道 → 微信 |

## 3.3 模块 C：文档处理

以下为三期规划功能，当前处于开发阶段。

面向货代操作中最耗时的文档类工作：

- **托书 OCR 录单**：拍照/截图即结构化提取（发货人/收货人/品名/件重尺/船名航次），1 分钟内完成人工 10 分钟的工作
- **提单草稿比对**：船公司草稿单 vs 客户确认单，自动标出差异项
- **单证模板生成**：输入关键信息，自动生成报关单/装箱单/发票模板
- **HS 编码推荐**：描述货物 → 推荐 HS 编码 + 监管条件 + 所需单证

## 3.4 模块 D：知识库

贯穿全流程的知识底座，面向企业内部知识管理：

- **内部 SOP 问答**：读取公司操作手册/规章制度，即时问答
- **历史案例检索**：典型操作记录可查，新人学习曲线缩短 50%
- **货代考试题库**：从业资格考试题目练习与解析

## 4.2 差异化优势

智能货代助手与竞品不构成直接竞争，而是在以下维度形成差异化切入：

1. **用户群体互补**：竞品聚焦年费可承受的中大型企业（全国约 1 万家），智能货代助手瞄准长尾 6 万家小微企业的个人操作员。两个市场几乎不重叠。

2. **部署门槛代际差**：竞品需企业级部署、系统对接、员工培训，从决策到上线平均 2-3 个月。智能货代助手内置在 Marvis 中，用户下载即用，零秒部署。

3. **定价维度突破**：竞品年费数万至数十万，天然排除个人操作员自费使用的可能性。智能货代助手基础免费、增值 10-30 元/月，属于"零决策成本"的个人消费。

4. **功能定位互补**：竞品强项在交易自动化（接单→报价→订舱闭环），这是需要耦合企业 ERP 的重资产能力。智能货代助手强项在信息赋能（查询/监控/提醒/文档），这是轻资产的个人提效工具，可以叠加在任何竞品系统之上使用。

5. **技术架构创新**：双通道监控架构（云端定时 + GitHub Actions 轮询）实现了零基础设施成本的 7×24 主动监控，竞品需要自建服务器或购买第三方监控服务。

## 4.3 护城河分析

短期内竞品难以复制的壁垒：

- **Marvis 生态绑定**：作为 Marvis 桌面端的内置 Skill，享有生态内的自然分发流量和用户黏性
- **零边际成本的监控架构**：GitHub Actions + 用户所选推送通道的组合依赖开源生态，竞品如果复制需要重新设计技术方案
- **社区驱动的知识库**：货代术语、SOP 问答等知识资产随时间积累形成数据护城河

# 第 6 章 技术架构

## 6.1 整体架构

智能货代助手基于 Marvis Agent 框架构建，作为桌面端内置 Skill 运行：

```
用户自然语言输入
        │
        ▼
┌───────────────────────────────────┐
│         Marvis Main Agent         │
│  ┌─────────────────────────────┐  │
│  │   智能货代助手 Skill        │  │
│  │                             │  │
│  │  ┌──────────┐ ┌──────────┐ │  │
│  │  │意图路由层│ │上下文管理│ │  │
│  │  │ 查询/监控│ │ 提单号   │ │  │
│  │  │ /文档/知 │ │ 航线偏好 │ │  │
│  │  │ 识库分发 │ │ 监控列表 │ │  │
│  │  └────┬─────┘ └──────────┘ │  │
│  └───────┼────────────────────┘  │
└──────────┼───────────────────────┘
           │
    ┌──────┼──────────────────┐
    ▼      ▼                  ▼
┌──────┐ ┌────────┐    ┌───────────┐
│web_  │ │file-   │    │create_    │
│search│ │agent   │    │scheduled_ │
│+fetch│ │analyze │    │task       │
│      │ │_image  │    │           │
└──────┘ └────────┘    └───────────┘
  实时      文档+       定时任务
  信息      OCR        引擎
```

## 6.2 核心架构特性

**零部署**：Skill 内置于 Marvis 桌面端，用户下载 Marvis 即可直接使用，无需安装任何额外软件或配置服务器。Marvis 框架自动处理模型调用、工具调度和上下文管理。

**双端覆盖**：纯提醒类监控通过 create_scheduled_task 实现云端定时，到期时 Marvis 同时向 PC 端和手机端推送通知，确保用户在任何设备上都能收到提醒。

**云+端混合**：查询类功能依赖 web_search/web_fetch 在 Marvis Agent 层完成（端侧调度云端服务），文档处理依赖本地 file-agent 和 analyze_image 能力，监控类按需走云端定时或外部 Actions，形成"云端能力+端侧执行"的混合架构。

## 6.3 二期监控架构（双通道）

智能货代助手在二期实现了两种监控执行模式的有机组合：

**通道一：纯提醒类（云端定时）**
- 适用场景：到港提醒、免费期预警
- 技术路线：用户对话 → create_scheduled_task（云端） → Marvis 调度引擎 → PC/手机双端推送
- 成本：零边际成本（Marvis 框架内能力）

**通道二：轮询监控类（GitHub Actions + 用户所选推送通道）**
- 适用场景：定时盯箱、运价波动提醒
- 技术路线：GitHub Actions（cron 定时） → curl 抓取船公司/平台页面 → 对比缓存 → 有变化时 用户所选推送通道推送
- 成本：零（GitHub Actions 免费 2,000 分钟/月 + 各推送通道均有充足免费额度）

## 6.4 技术选型理由

选择基于 Marvis Skill 框架而非独立开发 SaaS 的理由：

- 零基础设施成本：无需自建服务器、数据库、消息推送通道，全部复用 Marvis 生态能力
- 自然分发：Marvis 桌面端的用户增长直接转化为 Skill 的潜在用户，获客成本接近零
- 快速迭代：Skill 以 Markdown 配置文件 + LLM Prompt 为主，功能迭代周期从天级缩短至小时级
- 开源生态杠杆：GitHub Actions + 用户所选推送通道 等免费服务组合实现监控闭环，避免自建调度系统的高昂成本
